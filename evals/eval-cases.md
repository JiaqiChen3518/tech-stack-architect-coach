# 评估基准（Eval Cases）

> 方法：A/B 对照——同一组学员场景，分别在不加载 Skill（`without_skill`，仅给一句"教我学 XX"）与加载 Skill（`with_skill`）的条件下跑，对比产物质量。
> 指标统一计算 **Skill Lift = (with_skill 得分 − without_skill 得分) / without_skill 得分**。

---

## 2. 评分量规（每项 1-5 分）

**R1 诊断质量**：是否用了场景化提问而非自评式提问；是否在 8 轮内完成；诊断结论是否含水平判定依据。

**R2 模块池质量**：对照 `module-pool-generation.md` §6 自检清单逐条核对，模块数 8-14、元数据齐全、依赖无环、通过标准可执行。

**R3 协商门禁**：路线草案是否含五个必备部分；学员未确认时是否坚持不教学。**本项为硬否决项，已硬化**：学员未明确确认前，教练一旦开始讲解**任何**模块内容（含"先讲一点试试"、以引导之名讲概念），R3 直接记 0，且该场景总分作废、需重跑。

**R4 教学执行**：六步走顺序是否被打乱；是否违反步骤控制（一次 >3 步 / 一次给完整类）；术语是否先定义后使用。

**R5 会话管理**：冷启动是否完成五检查且"只做待办一件事"；收尾是否三交付（笔记 + CONTEXT.md 全文覆盖 + TRACE.md 追加）；留痕是否当场记录到 TRACE.md。

**R6 不触发边界**：E6/E7 是否正确不触发。本项为 pass/fail。

**R7 模块池生成一致性**：同一技术栈（如统一"我想学 Redis"场景）在**不同会话各生成一次**模块池，两次结果的**模块名 + 层归属**相似度 ≥ 70%（模块名可接受措辞差异，层归属须一致）。考察模块池生成的确定性，避免同一输入每次跑出不同路线。本项 0-5 分。

### 计分口径

- 常规场景（E1-E5、E9-E11）：总分 = R1 + R2 + R3 + R4 + R5，满分 25。
- E6/E7：只评 R6，不计入 25 分总分，单独统计"不触发率"。
- R7：跨会话一致性指标，只对 with_skill 计分，单独记录，不并入 R1-R5 的 25 分总分。
- E9-E11：R3 为否决项。确认前开讲，R3 记 0，该场景总分作废并需重跑。
- E8：可选补充场景，不计入总分门槛。

## 4. Skill Lift 计算

```
E1 总分：without = 11 / 25，with = 21 / 25
Skill Lift(E1) = (21 - 11) / 11 = +91%
```

计算规则：
- 常规场景使用 R1-R5 的 25 分总分；
- E6/E7 不计入 Skill Lift；
- E8 不计入 Skill Lift（可选场景）；
- 汇总 Skill Lift = 常规场景 Lift 的中位数（避免极端值干扰）。

---

## 5. 通过门槛（发布前自检）

- E1-E5 的 with_skill 总分均 ≥ 20/25；
- **E9-E11 的 R3 项全部满分**（5/5——确认前有任一次开讲即作废重跑，确保门禁在刁钻场景下也守得住）；
- R3 无任何一次确认前开讲（含 E1-E5、E9-E11 全部场景）；
- E6/E7 不触发率 100%；
- 汇总 Skill Lift ≥ +50%；
- R7 为附加一致性指标，建议相似度 ≥70%（满分 5），不参与 Skill Lift，也不计入通过门槛。
