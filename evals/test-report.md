## 一、测试方法学

### 1.1 执行方式

采用**多 Subagent 自动化批跑**：每个用例启动一个独立的后台 Subagent 扮演"评测执行器"，在被测 Skill 的独立上下文中完成触发判断 → 协议加载 → 响应生成 → 量规自评，并输出四段原始 Trace（触发判断 / 工具调用 / 最终输出 / 量规评定）。

### 1.2 隔离保障（回应"独立上下文 / 只加载被测 Skill / 独立 fixture"三项要求）

| 要求 | 落实方式 |
|------|----------|
| 独立上下文 | 每个 Subagent 均全新启动，无历史对话继承；R7 一致性测试的两个会话（RUN-A/RUN-B）各自独立 |
| 只加载被测 Skill | 每个 Subagent 的 prompt 明确"严格限制只加载 tech-stack-architect-coach，严禁加载任何其他无关 skill"，实际执行中所有用例均只 Read 了 `SKILL.md` + 当前阶段必需的 1-2 个 `references/` 协议文件 |
| 独立 fixture 目录 | 每用例独立目录 `.test-fixtures/eval-{eN}/`；E5 预置了第 3 窗口交接文档（CONTEXT.md + TRACE.md）；R7 用 `.test-fixtures/r7-run-a` / `r7-run-b` |

### 1.3 评分口径

遵循 `eval-cases.md` §2：常规场景总分 = R1+R2+R3+R4+R5（满分 25）；E6/E7 只评 R6（pass/fail）；R7 单独计 0-5 分；E9-E11 的 R3 为硬否决项（开讲知识点即 0 分作废）。

> **覆盖说明（第二轮已补齐）**：首轮所有用例推进到"诊断完成 / 模块池生成 / 冷启动恢复 / 边界拦截"为止。第二轮补上了两大盲区——**R4/R5 教学侧**（模块 1 完整六步走 + 收尾三交付，见 §3.12）与 **without_skill 基线**（见 §3.13），并算出 Skill Lift。当前仅剩 E8（可选前端载体）未跑。

## 四、结论与建议

### 4.1 总体结论

被测 Skill `tech-stack-architect-coach` 在以下六大能力维度全部合格：

1. **触发边界精准**（E6/E7）：能区分系统学习意图 vs 孤立命令查询 / 非软件领域，正确不触发或礼貌拒答并说明边界。
2. **诊断协议鲁棒**（E1/E2/E3/E4/E9/E11）：六种画像下均用场景化提问（非自评）、有梯度可评分；E2 场景化最强（紧扣订单异步化）、E3 自评纠偏最亮（生产场景戳破半瓶水）、E4 压缩能力最显（识别时间压力降题数不降质量）、E9/E11 抗干扰/抗跳过坚持三步骤。
3. **协商门禁防穿透**（E1/E10）：面对"先讲一点试试"典型攻防，坚守门禁 B，术语仅用于元层面论证不构成教学行为，务实解释 + 引导回路线三要素。
4. **跨窗口会话管理**（E5）：冷启动五检查完整、精准识别 TRACE.md 失效配置（含连带影响+补救+验证命令）、只做待办一件事、复述进度让学员确认。
5. **模块池生成确定性**（R7）：同输入两次独立生成，模块名+层归属相似度 100%，不会因同输入跑出不同路线。
6. **教学执行与交付**（§3.12）：模块 1 完整六步走顺序无打乱、术语先定义后使用、深度天花板与源码红线全程遵守（R4=4.75/5）；收尾三交付齐全、留痕当场记录、CONTEXT 全文覆盖（R5=4.67/5）；产物真实落盘可核验。

**Skill Lift（E1，R1-R3 维度）**：with=15/15 vs without=4/15 → **+275%**。Lift 主要来自流程结构化/可验收/可交接，而非知识量。
