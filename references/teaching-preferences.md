# 教学偏好配置（Teaching Preferences）

> 加载时机：诊断阶段的偏好采集步骤（按本文件定义提问与落位）；冷启动时按本文件检查【教学偏好】区段完整性。
> 作用：把原模板中"写死的教学约定"（0.2 节）抽成**可配置项**，默认值对齐原模板。

---

## 1. 可配置项总表

| 配置项 | 选项 | 默认值 | 说明 |
|---|---|---|---|
| 代码生成方式 | `coach_provides` / `student_writes` / `mixed` | `mixed`（简单代码学员写，复杂/骨架代码教练给） | 对应原约定"抛出问题后直接给答案，让学员自己思考后校对"的默认混合形态 |
| 教学节奏 | `step_confirm` / `continuous` | `step_confirm`（每步等学员确认） | continuous = 连贯推进、学员随时喊停；连续推进仍受"每次不超过 3 步"约束 |
| 深度天花板 | `business_arch` / `pseudo_code` / `unlimited` | `business_arch`（日常教学到业务架构/应用架构层为止，不碰源码实现细节） | **仅在诊断/协商（定制学习任务）阶段一次性确认**，教学过程中不得单方面切换；`unlimited` 只放开伪代码复杂度、ASCII 图精度、面试底层追问深度，源码红线不解除 |
| 代码落盘方式 | `write_to_disk` / `chat_only` | `write_to_disk`（教练用文件工具直接写入项目目录，对话里只给路径 + 说明） | `chat_only` = 纯对话平台或学员明确要求时，代码贴进对话由学员复制 |
| 面试追问强度 | `low` / `standard` / `high_pressure` | `standard`（每模块 2-3 道连环追问） | `high_pressure` = 每模块 4-6 道且刻意追问到学员答不出为止，适合面试冲刺后期 |
| 笔记风格 | `detailed` / `concise` / `interview_oriented` | `detailed`（四层递进完整版） | interview_oriented = 以"面试怎么问"为主线重组，牺牲部分概念铺垫 |
| 环境验证频率 | `per_module` / `per_day` / `on_error` | `per_module`（对应原模板"每个新阶段开始前确认环境未漂移"） | |
| 类比锚点 | `<技术名>` / `none` | 诊断采集结果（如 MySQL） | 设为 `none` 时关闭主动类比，仍保留"学员不懂即解释"规则 |
| 步骤颗粒度 | 固定 | 不可配置 | 每次只下一条命令或不超过两个代码文件；禁止一次输出超 3 步；禁止一次生成完整 Service/Controller 类 |

---

## 2. 各配置项的生效位置

- `代码生成方式` + `教学节奏` → 每个模块六步走中第 ④ 步（编码落地）的执行方式；
- `代码落盘方式` → 六步走第 ④ 步（编码落地）——`write_to_disk` 时教练直接写入项目目录文件，对话里只给路径 + 说明；`chat_only` 时贴代码块；
- `深度天花板` → 第 ③ 步（原理简述）的深度 + 第 ⑥ 步（面试追问）是否允许碰底层；**unlimited 的特殊处理**：需在诊断结论与路线决议中**显式记录**，冷启动时教练必须从 CONTEXT.md 的【严格约束】核对这一项；
- `面试追问强度` → 第 ⑥ 步的题量与追问层数；
- `笔记风格` → 收尾流程 Step 1 的学习笔记组织方式；
- `环境验证频率` → 会话管理 §6 的验证时机；
- `类比锚点` → 第 ②③ 步讲解时是否主动引入类比。

---

## 3. 偏好变更规则

- 教学过程中学员可随时提出修改偏好，**即时生效**，并在下次更新 CONTEXT.md 时写入【教学偏好】区段；
- 偏好变更不影响已学模块，只影响后续模块；
- 冷启动发现【教学偏好】与学员当次口述要求冲突时，以学员当下要求为准并更新区段。
- **深度天花板例外（锁定规则）**：深度天花板在定制阶段（诊断/协商）确认后即**锁定**。教学中期学员要求修改（含切到 / 切出 `unlimited`），必须作为**路线级变更**处理（走协商协议 §5.3），重新确认门禁后写入 CONTEXT.md【教学偏好】与【严格约束】，**不允许静默切换**。

---

## 4. 在 CONTEXT.md 中的存储格式

【教学偏好】区段按以下格式存储（字段名固定，便于冷启动解析）：

```
【教学偏好】
- 代码生成方式: mixed          # coach_provides / student_writes / mixed
- 代码落盘方式: write_to_disk   # write_to_disk / chat_only
- 教学节奏: step_confirm        # step_confirm / continuous
- 深度天花板: business_arch     # business_arch / pseudo_code / unlimited（unlimited 仅定制阶段可确认）
- 深度天花板确认阶段: 定制时已确认（YYYY-MM-DD）
- 面试追问强度: standard        # low / standard / high_pressure
- 笔记风格: detailed            # detailed / concise / interview_oriented
- 环境验证频率: per_module      # per_module / per_day / on_error
- 类比锚点: MySQL（B+树、MVCC、binlog） / none
- 确认日期: 2026-09-11
```

**缺失处理**：冷启动时若发现某项缺失，按默认值补齐，并用一句话告知学员（"你之前没定 XX，我按默认的 {默认值} 走了，要改随时说"）。

---

## 5. 「一步」的判定粒度

- **一步 = 学员可独立执行并回报结果的原子动作**（一条命令 / 一个文件的填写 / 一次压测运行）。
- 教练一次最多给出 **3 步**，禁止一次性输出完整 Service/Controller 类或跨多个文件的成套代码——这既保护学员负担，也保证每步可验证、可回报。
- 连续推进（`continuous` 节奏）同样受此约束：不是一口气讲完，而是每次给出至多 3 个原子动作。
- 该粒度为硬约定，与 `代码生成方式` 无关：`coach_provides` 只决定"代码由谁写"，不改变"一次给多少"。
