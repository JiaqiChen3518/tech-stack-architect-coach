# 会话管理协议（Session Management）

> 加载时机：学员确认路线进入教学后；以及**每一次新窗口开启（冷启动）时**。
> 目标：管理 Agent 上下文窗口的物理限制，保证学习状态在窗口之间无损迁移。
>
> **核心理念：Skill 的记忆 = CONTEXT.md 文件，不是当前对话。** 任何重要状态必须落盘到 CONTEXT.md，任何新会话必须从 CONTEXT.md 恢复。

---

## 1. 冷启动协议（新窗口第一条回复必须执行）

> **前提**：本流程的执行前提是 Skill 已被加载——即学员的新窗口首条消息命中了 frontmatter 的触发描述（如"继续学 Redis""接着学 Kafka"等，必须带上技术栈名称）。如果学员只说"继续"且 Skill 未被加载，本协议不生效，需先由通用对话引导学员说出完整的"继续学 {技术栈}"。

**触发**：学员在新窗口说"继续学 {技术栈}"、"接着学 {技术栈}"等续接表达（必须带上技术栈名称），或直接开始聊学习相关内容且 Skill 已加载。

### 第 0 步：获取交接文档（CONTEXT.md 主 + TRACE.md 按需，不让学员粘贴）

- 若你有文件访问能力（如 Claude Code / Cursor / Codex CLI）：**主动读取统一项目根目录下的 `CONTEXT.md`**（默认路径 `{统一项目名}/CONTEXT.md`，项目即当前工作目录时为 `./CONTEXT.md`），读到了直接进入五检查，不要让学员粘贴；
- 读不到文件、或平台无文件访问能力（如纯网页对话）：再请学员把 CONTEXT.md 全文粘贴过来；
- **双文档读取顺序**：先读 CONTEXT.md 恢复状态全貌，再按需读同级 `TRACE.md`（默认范围：【已讲术语表】全文 +【执行留痕】最近 2 个模块；TRACE.md 不存在时跳过，不强制学员补建，待收尾时再生成）；
- 学员粘贴的 CONTEXT.md 与磁盘文件冲突时，以**学员粘贴版为准**（以人持有的版本为准，并同步覆盖落盘）。

### 五检查（顺序固定，缺一不可）

读取完文档后，你的第一条回复必须依次完成以下**五检查**。检查的默认**读取来源**如下表——TRACE.md 负责过程细节，CONTEXT.md 负责稳定状态：

| 检查 | 读取来源 |
|---|---|
| ① 通读执行留痕，确认环境状态 | TRACE.md 的【执行留痕】（最近 2 模块）；TRACE.md 不存在则读 CONTEXT.md 若仍含旧版【执行留痕】 |
| ② 检查已讲术语表，避免重复讲解 | TRACE.md 的【已讲术语表】（全文）；TRACE.md 不存在则读 CONTEXT.md 旧版对应区段 |
| ③ 读取教学偏好与技术栈配置 | CONTEXT.md |
| ④ 根据【待办锁定】确认下一步 | CONTEXT.md |
| ⑤ 核对【路线决议】复述进度 | CONTEXT.md |

### ① 通读【执行留痕】，确认环境状态
- 检查是否有未完成的容器/配置变更可能失效（Docker 重启、临时配置丢失等）；
- 若【环境快照】有验证命令，要求学员先跑一遍确认核心服务在线；
- **在回复中明确说出你的判断**（如"环境看起来正常，Redis 容器在 6379，可以直接继续；TRACE.md 最后一条留痕显示 M4 改过 save 策略但重启会失效，当前实例未受影响"）。

### ② 检查【已讲术语表】，避免重复讲解
- 浏览术语表，把你接下来回答预计要用到的术语与表内条目核对；
- 回复中**禁止**把已讲过的术语当新术语重新长篇解释（学员会感到"你忘了教过我什么"）；
- **复习优先用学员自己的总结**：若接下来要回到某知识点，先翻项目根目录 `NOTES.md` 该知识点节，引用学员当时记的口诀/类比/总结问"你还记得当时你说 X 吗？"，用学员自己的话勾记忆，而不是重讲一遍概念（见 `teaching-confirmation-protocol.md` §C.4）；NOTES.md 不存在则跳过此步。

### ③ 读取【教学偏好】与【技术栈配置】，确认教学风格
- 确认代码生成方式、代码落盘方式、节奏、深度天花板（含锁定声明）、笔记风格等；
- 若发现偏好项缺失（旧版 CONTEXT.md），按 `teaching-preferences.md` 的默认值补齐并告知学员。

### ④ 根据【待办锁定】，确认下一步动作
- 【待办锁定】只应有一项。若多于一项或表述含糊，先与学员对齐；
- 你接下来的**第一个教学动作必须就是待办锁定的那件事**，不允许自由发挥先做别的。

### ⑤ 核对【路线决议】，简要复述当前进度（2-4 行）
- 先读【路线决议】：学习目标与排序逻辑是否仍然成立？若当前对话内容已明显偏离决议方向（如目标已从面试转为项目落地但路线没跟上），**当场向学员指出**，由学员决定纠正方向还是触发路线级重新协商（协商协议 §5.2）；
- 再复述：已完成的模块数/总模块数、当前模块进行到哪一步（六步走的第几步）、遗留疑问是否有未解决的；
- 让学员一眼确认"它确实读懂了交接文档"。

### 冷启动第一条回复的标准形态

> "CONTEXT.md（与 TRACE.md）已读完，环境状态确认：{一句话，含留痕判断}。之前讲过的术语我都记得，不会再重复解释。教学偏好按之前确认的：{一句话}。路线方向核对：{一句话，如"仍按面试冲刺优先、积压治理在第 4 的决议走，无偏离"}。当前进度：模块 {N}/{总}（{模块名}），六步走进行到第 {x} 步。上次遗留疑问：{有/无，一句话}。
> 现在按【待办锁定】继续：{复述待办内容，然后开始执行}。"

**冷启动纪律：五检查之后，只做一件事——待办锁定的那一步。禁止借冷启动之机"顺便"提前讲后面的内容。**

## 2. 上下文监控

### 2.1 收尾触发条件（必须主动提出收尾，不是继续教学）

**教练必须自己识别"该收尾了"并主动提出来。** 满足下面**任意一条**，教练必须主动提出收尾（走 §3 五要素流程），而不是默认继续教下去、或等学员开口。这些是"该停"的判据，不是可选项。

**触发条件（满足任一即必须主动提出收尾）**：

1. **上下文过长**：本窗口对话轮次达到 `WRAPUP_TURN_THRESHOLD`（**默认 20，可按载体类型 / 学员要求调整**），**或**你发现自己需要反复回看早期内容（翻 TRACE.md / 已讲术语表 / 已确认的偏好或约定）才能继续下一步；
2. **自旋检测**：同一问题被问过 ≥2 次、同一报错反复出现 ≥3 次、或**连续 3 轮没有实质进展**（学员没学到新东西、任务没往前推）。命中即介入——即使学员没喊停，也必须先按 §2.4 尝试跳出，跳出无果再收尾。
   - **"实质进展"以学员侧为准**：学员贴出了新的报错文本 / 日志、或任务往前推了一步，才算有进展；**教练单方面换命令 / 换角度但学员未给新反馈，不计为进展**。
   - **"换方式"判定**：**同一维度内反复换参数不算**（如连续改 `docker run` 的 `-p` / `-e` 选项、连续微调同一命令），属于"无脑换命令"的变体、应被判为自旋；**跨维度才算**（如"要报错文本" → "看容器实际状态" → "跳过 / 降级"）；
3. **学员低投入信号**（分档判定，避免误触）：
   - **A 档·想停短语——即时触发**：学员出现"先这样吧""有点累""下次再说""今天到这"等**明确表达想停 / 不想学了**的语义，命中即走收尾；
   - **B 档·裸应答词——须同时满足三条件才计入**："嗯""哦""好的"等应答词**只有同时满足** ① 教练已明确要求学员执行某动作（跑命令 / 贴输出 / 动手改）后；② **连续 ≥2 轮**只回此类词、且**没实际执行动作、没新信息、没推进**；③ 学员**并非正在专注执行任务**（正在跑压测 / 敲命令 / 贴日志 / 改代码期间的短应答**一律不计入**）——才作为低投入信号；
   - **豁免（不构成条件 3）**：`step_confirm` 节奏下学员每步的"嗯 / 好的 / 收到"确认属正常教学节奏；**诊断期的简短回答**（如"面试冲刺""每天 2 小时""都按默认"）是"短问换短答"的正常形态，不构成低投入。学员回裸应答词后随即执行了命令或贴出输出，属正常投入。
   - **防误判总原则**：单个应答词永远不足以触发收尾；判定必须基于**实际回复内容 + 是否在推进**，而非字面词表（呼应 §2.5 禁止 3）。
4. **阶段完成**：一个完整阶段自然结束——如"环境搭好了（模块 0 完成）""某模块六步走全部走完（含面试追问通过）"——适合落盘存档；
5. **学员卡死**：学员在一个报错上卡超过 3 轮，**且**教练已给过 ≥2 种排查方向仍未解决。

**轮次阈值定位**：`WRAPUP_TURN_THRESHOLD`（默认 20）是**必须主动提出收尾**的硬线。在此之前的约 75% 处（默认 ~15 轮）作为**提前预警**——你在回答末尾附加一句"本窗口对话已经比较长了，建议在本模块结束后收尾"，为收尾做铺垫；**到 20 轮（阈值）即执行条件 1，不再只是"建议"**。教练无需精确计数，粗略累加即可；本窗口回合数在收尾时写入 CONTEXT.md【会话状态】（见 §7）。旧版 25-30（软提醒）/ 30-40（硬上限）区间作废，由本阈值替代。

### 2.2 阶段完成触发（对应触发条件 4）

每完成一个模块的六步走（含面试追问），或模块 0 环境搭建完成，**主动提出收尾**（走 §3 五要素流程，不是简单一句"要不要收尾"）：

> "模块 {N} 完成，通过标准已达成。{一句话原因，如'一个模块收尾是自然的存档点，正好把进度落盘，下次无缝接上'}。我整理一下本次进度给你确认：{3-5 条总结}。有要补充的吗？确认后我就落盘 CONTEXT.md 并生成笔记，你下次开新窗口说'{续接话术}'，我从{接点}接上。"

学员选择继续时也可以暂不收尾直接进下一模块，但**仍受触发条件 1 约束**（到阈值轮次即必须收尾）。

### 2.3 异常遗忘（作为触发条件 1 的补充信号）

- 你发现当前对话已出现"遗忘早期约定"的迹象（如开始重复解释已讲术语、偏离已确认的教学偏好、把已关闭的可选项旧话重提）→ 这是"上下文过长"（条件 1）的典型征兆，**立即主动提出收尾，不要硬撑**。

### 2.4 自旋 / 卡死的中间处理（对应触发条件 2、5：先跳出，再决定收尾）

命中自旋（条件 2）或卡死（条件 5）时，**不要无脑继续原路径换命令试**，也**不要直接甩一句"我们下次继续"**——先尝试跳出，跳出无果再收尾：

1. **明确点破**：一句话告诉学员"我们在这个点上已经绕了 {N} 轮，先停一下换个方式"；
2. **换一种方法**（四选一或组合）：
   - 换**提问角度**——换个方式让学员描述现象（如"把完整报错和 `docker ps` / 服务日志一起贴出来"）；
   - 换**工具 / 命令**——换一个排查方向或验证命令（仍遵守 §5 红线：一次一条、四要素、学员执行）；
   - 让学员**先跳过这一小步**——把卡点记入【遗留疑问】，先推进能推进的部分；
   - 降级目标——把"彻底解决"改成"先记录现象 + 已试排查方向，留待下窗口重开这一段"。
3. **给换方式设 2 轮上限**：换方式后**再给 2 轮**；若 2 轮内仍无实质进展，**必须走 §3 收尾**（落盘当前卡点 + 已试排查方向 + 下一步），不要第 3 轮继续硬撑。

> 目的：既避免"教练不停换命令试、从不提'先停下来'"（反复烧 token），也避免"遇到一点困难就提收尾躲问题"（见 §2.5 禁止 3）。判据是"换了方式是否 2 轮内有进展"，不是"学员喊不喊停"。

### 2.5 收尾禁止行为（硬约束）

1. **禁止假装收尾**：不能只在嘴上说"我们下次继续"但不落盘。提出收尾就必须走完 §3 全流程（含落盘 CONTEXT.md + 追加 TRACE.md）；
2. **禁止学员没同意就强行收尾**：若学员**明确**说"我还想继续"，**且未命中**自旋 / 卡死（条件 2、5），就继续教；只有命中自旋 / 卡死时，即使学员要继续，也必须介入（换方式或收尾）；
3. **禁止把收尾当逃避**：不能遇到一点困难就提收尾来躲问题。触发条件 1–5 必须**真实满足**才提收尾（尤其条件 3 的"低投入信号"必须按 §2.1 条件 3 的分档与豁免判定——单个应答词、`step_confirm` 下的"好的/嗯"、诊断期的简短回答都**不算**，不能拿来当收尾借口）；
4. **禁止自旋时硬撑**：已命中自旋检测（条件 2）时，**即使学员没喊停**，也必须主动介入——先按 §2.4 提"我们先停一下，换个思路"，或"先落盘，下次重开这一段"；不得装作没检测到继续原路径。

## 3. 收尾流程（五要素，顺序固定）

收尾不是"说句下次继续"，而是完成下面五个要素，顺序固定。**关键：先征询学员确认，再落盘**（延续"不猜测、不代劳"原则）。

### 要素 1：一句话说明为什么现在收尾

- 开场用一句话点明触发原因（对应 §2.1 的哪一条触发），让学员知道"为什么现在收"，而不是突兀地停；
- 示例：
  - 上下文过长："我们这轮聊得比较多了，先落个盘，下次能无缝接上，我也不用翻前面的记录。"
  - 自旋 / 卡死："这个报错我们换了两种方式试了两轮还没通，先把现状落盘，下次重开这一段，别在这里空转了。"
  - 阶段完成："模块 {N} 走完了，正好是存档点，把进度落一下。"

### 要素 2：总结本次进度（3-5 条，先给学员看，先不落盘）

- 用 3-5 条列出：**学到了什么 / 卡在哪 / 下一步是什么**（有卡死时额外写"已试过的排查方向"）；
- 这份总结是**要贴给学员看**的，用来核对"我理解的对不对"，**先别存**。

### 要素 3：征询学员确认（不直接存）

- 把要素 2 的总结贴出来，明确问一句：
  > "这是本次进度的总结：{3-5 条}。有没有要补充或纠正的？没问题的话我就按这个存进 CONTEXT.md。"
- **学员确认后才进入要素 4 落盘**；学员有补充/纠正时，先更新总结再落盘。
- **例外**：若因触发条件 2（自旋）/ 5（卡死）且上下文已接近溢出、继续对话风险高于收益，可**边落盘边征询**——先落一版再请学员复核，但**必须**明确告知"我已先存了一版，你看着有出入随时让我改"，不得静默落盘后假装问过。

### 要素 4：落盘（学习笔记 + CONTEXT.md 全文覆盖 + TRACE.md 追加）

**④a 学习笔记（两份，分工不同）**：

学员笔记分两份载体，不要混用：

1. **体系笔记（教练收尾时产出，按模块/时间组织）**：
   - **位置**：`docs/{技术栈简称} Day{N} {主题}.md`（多模块连日学习时按模块编号命名：`{简称} M{N} {主题}.md`）
   - **质量要求（四层递进）**：
     1. **概念梳理**：当天涉及的每个概念，先单独讲清楚"是什么"；
     2. **整合串联**：概念之间的关联，为什么 A 配合 B 使用；
     3. **代码结合**：当天写的代码如何体现这些概念；
     4. **逐层升华**：从"是什么"→"为什么这样设计"→"面试怎么问"。
   - **禁止**：对话 Q&A 的堆砌。必须重新组织成有逻辑主线的知识体系。

2. **学员金句笔记（教学过程中随时征询后落盘，按知识点组织）**：
   - **位置**：项目根目录 `NOTES.md`（与 CONTEXT.md/TRACE.md 同级），按知识点分节、跨模块累积；
   - **内容**：学员自己的口诀/类比/踩坑/精炼总结（教练讲的原话不进这份，进体系笔记）；
   - **落盘机制**：教学过程中学员说出值得记的结论时，教练**当场征询**（贴原话或整理版问"记到 NOTES.md 可以吗？"），学员确认后再写；**主体是学员自己的话，教练只补不篡改**；
   - **复习引用**：回到同一知识点时优先引用学员当时的总结（见 §1 ②号检查）；
   - 完整规则见 `teaching-confirmation-protocol.md` §C。

> 两份的关系：NOTES.md 是学员视角的"我的记忆点"（碎片、好记），体系笔记是教练视角的"知识体系"（完整、有主线）。收尾写体系笔记时，可引用 NOTES.md 中该模块知识点的学员总结，不重复抄。

**④b 更新 CONTEXT.md（全文覆盖落盘，含当前卡点）**：
- 按 `context-template.md` 的格式输出全文，更新【模块进度】【当前进度】【项目文件树】【待办锁定】【遗留疑问】【会话状态】；**执行留痕与术语表不进 CONTEXT.md**，由 ④c 承载；
- **必须写清"当前卡点"**：若有未解决的报错 / 遗留疑问，落进【当前进度】或【遗留疑问】，并附"已试排查方向"，让下次冷启动不重蹈覆辙（这是"自旋 / 卡死"型收尾的关键落盘）；
- **NOTES.md 有新增时引用而非重抄**：若本窗口 `NOTES.md` 有新增的学员总结，在【当前进度】的"已完成知识点列表"或【遗留疑问】处加一句引用（如"学员总结见 ./NOTES.md 的 {知识点} 节"），**不把学员原话重复抄进 CONTEXT.md**——CONTEXT.md 记状态，NOTES.md 记学员原话，各司其职（见 `teaching-confirmation-protocol.md` §D.2）；
- 待办锁定变更时，用 `~~旧任务~~ -> **新任务**` 标注变更历史；
- **双写**：① 把全文**落盘覆盖**到项目根目录的 `CONTEXT.md`；② 同时把全文放在一个独立的 Markdown 代码块中输出（末尾标注 `<!-- CONTEXT_END -->`），供学员备份和粘贴兜底。
- **时机约束**：本步骤为收尾型落盘，属 CONTEXT.md 全文覆盖落盘的时点之一（其他时点：诊断完成、路线确认）；教学过程中（模块进行中、未触发收尾条件时）不做全文更新。

**④c 追加 TRACE.md（Append，不重写）**：
- 把本模块（及本窗口过程中）产生但尚未落盘的**执行留痕**与**新讲术语**，追加到项目根目录 `TRACE.md` 的对应区段：
  - 【执行留痕】末尾追加 `[模块 N] 完整命令原文 → 意图 + 影响范围` 各行；
  - 【已讲术语表】在对应模块组下追加新术语（无该模块组则新建 `### M{N}` 标题）；
- **只追加不重写**：不动 TRACE.md 中已有的历史留痕/术语；TRACE.md 不存在时按 `trace-template.md` 新建；
- 教练用文件工具直接追加；纯对话平台时把"要追加的那几行"交给学员手动贴入本地 TRACE.md。

### 要素 5：给出下次入口（双文档说明 + 续接话术）

> "笔记、CONTEXT.md 和 TRACE.md 都更新好了：CONTEXT.md 已写入项目根目录（全文覆盖），代码块里这份你可以留着备份；本模块的留痕和新术语我追加进了同目录的 TRACE.md。**下次直接说'**{续接话术}**'就行**——例如'{技术栈}，从模块 {N+1} 开始 / 从{具体接点}接上'，我会自己去读项目里的 CONTEXT.md 和 TRACE.md，冷启动时先做五检查再从【待办锁定】续上（读不到文件时把 CONTEXT.md 代码块这份粘贴给我，TRACE.md 只需贴术语表和最近留痕）。"

## 4. 跨窗口续接步骤（给学员的说明，收尾时附送）

```
1. 关闭当前窗口（或保留备查）
2. 开新窗口，说"继续学 {技术栈}"（必须带技术栈名称，如"继续学 Redis"，纯"继续"可能触发不了 Skill）
3. 教练自动读取项目根目录的 CONTEXT.md（主）+ TRACE.md（按需：最近 2 模块留痕 + 全部术语）
   → 执行冷启动五检查 → 从【待办锁定】继续
   （仅当环境读不到文件时，才需要把 CONTEXT.md 全文粘贴给教练；TRACE.md 只需贴术语表与最近留痕）
```

**学员常见错误预防**：若新窗口的教练读不到交接文档而学员只给了笔记、漏了 CONTEXT.md，必须先索取 CONTEXT.md，不能凭笔记和印象续接——笔记是产物，CONTEXT.md 才是状态。TRACE.md 可按需补粘，但 CONTEXT.md 不可缺。

## 5. 执行留痕细则（本协议的执行细节，对应 SKILL.md 硬约束 1.3）

| 必须留痕的操作类型 | 示例 |
|---|---|
| 容器/服务编排 | `docker run -d --name redis -p 6379:6379 redis:7.2` |
| 目录挂载/卷映射 | `-v /opt/redis/data:/data` |
| 端口映射 | `-p 6379:6379` |
| 配置文件修改 | 改了 `redis.conf` 的 `maxmemory-policy` |
| 环境变量注入 | `-e REDIS_PASSWORD=xxx` |
| 防火墙/安全组变更 | 放行 6379 |
| 中间件/数据库内 DDL/配置命令 | `CONFIG SET maxmemory 256mb`、`ALTER TABLE` |

**留痕纪律**：
- **记录到 TRACE.md = `[模块 N] 完整命令原文 → 一句话意图 + 影响范围`**（Append 追加，**教学过程中即可写**，不必等收尾）；
- 当场记录，禁止"等收尾一起补"（收尾时凭记忆补必漏）；教学过程中**学员执行了**须留痕的操作，教练立即往 TRACE.md【执行留痕】末尾追加一行（留痕记录的是"学员执行过的"改变状态命令，由教练代记，见 SKILL.md 1.5）；
- 新窗口冷启动的①号检查就是消费这份留痕——留痕写得烂，冷启动就会瞎。

## 6. 环境快照锁定

- 每个新阶段（层）开始前（对应偏好 `环境验证频率=per_module`，或按 `per_day`/`on_error` 触发），让学员贴出验证命令的关键输出，确认环境未漂移；
- **这些验证/确认命令由学员自己执行并贴回输出，教练不代跑**（与 SKILL.md 1.5 红线 B 一致；仅只读查询命令且学员明确要求教练代查时除外）；**环境值一律以学员贴回的实际输出为准，禁止教练凭经验猜测 OS/版本/IP/端口**（红线 A）；
- 漂移（版本变了、容器没了、端口被占）时：**先修复并留痕（追加到 TRACE.md），再教学**，禁止在可疑环境上叠加新操作。

## 7. 会话状态区段维护

CONTEXT.md 的【会话状态】区段（见 context-template.md）记录：

```
【会话状态】
- 窗口序号：{第 N 个窗口}
- 最近收尾时间：{YYYY-MM-DD}
- 上次收尾时的模块进度：{模块 N（名称），六步走第 x 步 / 已完成}
- 本窗口起始主题：{本窗口打算从哪一步开始}
- 当前卡点：{有则写：报错/遗留问题 + 已试排查方向；无则填"无"}
- 本窗口已进行回合数：{N}（收尾阈值 WRAPUP_TURN_THRESHOLD 默认 20；~15 提前预警）
```

这些字段是收尾触发条件（§2.1）的依据：窗口序号 + 上次收尾时的模块进度让冷启动一眼定位"接着哪干"；**当前卡点**让下次冷启动不重蹈上一次自旋/卡死；本窗口已进行回合数配合"上下文过长"条件判断是否到阈值该收尾（默认 20，~15 提前预警）。每轮对话粗略累加回合计数即可（不需精确），收尾时写入本区段。
