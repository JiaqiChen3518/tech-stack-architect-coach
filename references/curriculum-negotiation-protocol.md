# 方案协商协议（Curriculum Negotiation Protocol）

> 加载时机：诊断完成 + 模块池生成并通过质量自检之后。
> 目标：把"教什么、按什么顺序、花多长时间、产出什么"摆到桌面上，**与学员达成一致后才允许开始教学**。
>
> **本协议是全 Skill 最重要的门禁：学员未明确确认前，禁止进入任何教学行为。**

---

## 1. 协商流程总览

```
生成路线草案 → 结构化呈现 → 收集反馈（可多轮）
→ 调整草案 → 再次呈现 → 学员明确确认 → 建档（写入 CONTEXT.md）→ 进入教学
```

---

## 2. 路线草案模板

呈现给学员的路线草案必须包含以下五个部分，缺一不可：

```markdown
## {技术栈} 学习路线草案

### 一、诊断结论回顾
（3-5 行：基础水平 / 目标 / 类比锚点 / 建议方向——来自诊断结论，让学员确认"你理解的我"是对的）

### 二、建议路线（按顺序）
| 顺序 | 模块 | 层 | 学习内容（一句话） | 通过标准（一句话） | 预估时长 |
|---|---|---|---|---|---|
| 1 | 五大数据结构实战 | 基础层 | String/List/Hash/Set/ZSet 在项目里的正确使用 | 五种类型的典型场景各写一个 Demo 并压测 | 1 天 |
| 2 | …… | …… | …… | …… | …… |

### 三、总时长与节奏
- 预估总时长：{X} 天（按 {偏好：单步确认/连续推进} 节奏）
- 每周学习天数假设：{默认 3-4 天，与学员确认}

### 四、最终产出
- 一个 {项目名} Spring Boot 项目，包含 {N} 个可复用组件（列举）
- {X} 篇分层学习笔记（docs/ 目录）
- 一份已填好的 CONTEXT.md 交接文档

### 五、可选调整项
- 想压缩总时长？可考虑：{列出可降级为快速验证的模块}
- 想跳过基础？{入门学员无此选项；用过/深入学员列出可跳模块}
- 想加深某块？{建议可加深的模块及加深方式}
```

### 2.1 呈现话术

> "路线我给你排好了，先看一眼有没有问题。这份草案是按你的目标（{目标}）排的——{一句话说明排序逻辑，如'面试权重高的往前提了'}。重点看三块：**总时长**、**有没有你想跳过或加深的模块**、**最终产出是不是你想要的**。确认没问题我们就按这个走。"

## 3. 反馈收集规则

### 3.1 学员可以调整的四个维度

| 维度 | 处理方式 |
|---|---|
| 总时长 | 给出"压缩/拉长"的等价方案：压缩 = 列可降级为快速验证的模块；拉长 = 标出可拆细的模块 |
| 模块取舍 | 学员要跳过某模块时，**必须检查其是否为后续模块的 prerequisites**；若是，说明依赖关系并给出"改为快速验证"作为折中，而不是硬跳 |
| 顺序调整 | 允许在不违反依赖拓扑的前提下调整；学员要求的顺序违反依赖时，用一句话解释为什么不行，并给出最接近的合法顺序 |
| 最终产出 | 增删产出物（如增加"输出一篇技术博客"），同步调整对应模块的通过标准 |

### 3.2 收集话术

> "有想调整的地方吗？没有的话回复'确认'，我们就从第一个模块开始。"

### 3.3 修改后必须重新呈现完整草案

任何调整（哪怕只改一个模块）后，**重新输出完整草案全文**（不是增量补丁），让学员基于全貌做最终确认。防止"改着改着跑偏"和"各说各话"。

---

## 4. 确认门禁（硬约束）

- **什么算确认**：学员明确说"确认 / 可以 / 没问题 / 就这样 / 开始吧"等。**沉默不算，"都行"要追问一句"那我就按草案执行了？"，得到肯定答复才算。**
- **确认后动作**：
  1. 把**确认后的完整路线决议**写入 CONTEXT.md（落盘到统一项目根目录）的【路线决议】+【模块进度】+【待办锁定】+【技术栈配置】+【学员画像】+【教学偏好】+【环境快照】区段（首次搭建/验证产生的留痕写入 TRACE.md 的【执行留痕】，Append 追加）。本次落盘按 CONTEXT.md 全文覆盖执行——只写模块表而不写"为什么这么排"，新窗口就会丢方向；
  2. 建立/更新统一项目骨架；
  3. 宣布"现在开始模块 1"，进入教学。
- **严禁行为**：确认前以"先感受一下"为由开始讲解任何模块内容；确认前帮学员写项目代码。协商阶段只允许讨论"学什么"，不允许"开始学"。

---

## 5. 执行中调整机制（路线变更）

教学开始后，学员可能要求改路线。分两级处理：

### 5.1 模块内调整（轻量，教练可直接决定）

- 某模块学起来比预期难/易 → 调整该模块内的讲解深度与速度，**路线表不动**；
- 学员对某模块的通过标准有异议 → 当场协商该模块的通过标准，更新 CONTEXT.md。

### 5.2 路线级调整（重量，必须重新协商）

触发条件（任一）：
- 学员主动提出重排/增删模块；或
- 同一模块的实际学习耗时已超过预估时长的 1.5 倍仍未通过；或
- 学习目标发生变化（如"我本来为面试，现在项目急需用 XX"）。

处理流程：
1. 暂停教学（当前模块先收尾到可交接状态）；
2. 基于**剩余模块池**重新生成路线草案（沿用本协议 §2 模板）；
3. 重新走确认门禁（§4）；
4. 更新 CONTEXT.md【路线决议】（新目标、新排序逻辑、新确认日期）与【模块进度】，待办锁定变更为新路线的下一步。

**话术参考**：

> "没问题，路线本来就该跟着实际情况走。我重新排一下剩余的模块，你看过确认了我们再继续。"

### 5.3 深度天花板调整（按路线级变更处理）

教学过程中学员要求切换深度天花板（含切到 / 切出 `unlimited`）时，**不得静默切换**，统一按 §5.2 的路线级变更处理：

1. 暂停教学；
2. 与学员重新确认新天花板的真实语义——若切到 `unlimited`，**必须当面重申源码红线不解除**（仅放开伪代码复杂度、ASCII 图精度、面试底层追问深度）；
3. 重新走确认门禁（§4），确认通过后把新值同步写入 CONTEXT.md 的【教学偏好】（深度天花板）与【严格约束】（锁定声明），并标注新的确认日期；
4. 若此前因旧天花板回避了某些底层模块，回看剩余模块池是否需要相应加深或补充。

## 6. 协商阶段的环境事项（模块 0 操作细则 · 对应 SKILL.md 红线 A/B）

- 若诊断发现学员环境未搭建：路线草案第一行固定为"模块 0：环境搭建与验证（0.5 天）"，产出即**已锁定的环境快照表**（格式见 `context-template.md` 的【环境快照】），搭建过程中的所有命令按执行留痕规则记录。
- 协商阶段若发现学员对技术栈的期待与模块池覆盖范围明显不符（如"我想学 XX 的源码级调优"但源码红线不允许），**当场说明边界并给出替代方案**，不要等教学中途爆雷。

### 6.1 红线 A 细则：环境逐项确认，禁猜

模块 0 开始前，**逐项、一次只确认一个**环境项（延续诊断的"一轮一问"，禁止一次抛出一堆环境问卷）。确认哪些项、按什么顺序，取决于本模块要装的东西——**只确认当前这一步真正依赖的那一项**，不要为了"备齐"而过度盘问。

| 环境项 | 该确认吗（何时） | 学员自查命令（教练不代猜，只让学员贴回） |
|---|---|---|
| 操作系统及版本 | 装包前必确认（决定用 `apt`/`yum`/`brew`/`winget` 等哪条路） | `cat /etc/os-release`；Windows：`ver` 或 PowerShell `$PSVersionTable.PSVersion` |
| 架构 | 涉及二进制/容器镜像时确认 | `uname -m`；Windows：`echo %PROCESSOR_ARCHITECTURE%` |
| IP / 主机名 | 只在需要跨机访问/连虚拟机时才确认，**绝不默认 IP** | `ip addr`；Windows：`ipconfig` |
| 网络模式（NAT/桥接/仅主机） | 虚拟机且需要跨机访问时确认 | 看虚拟机构建（VMware/VirtualBox 的网络适配器设置） |
| 已装软件版本（JDK/Docker/依赖库等） | 装下一个依赖前确认 | `java -version` / `docker --version` / `node -v` 等 |
| 端口占用 | 起服务前确认目标端口没被占 | `ss -tlnp \| grep <port>`；Windows：`netstat -ano \| findstr <port>` |
| 是否有 Docker | 决定走容器还是原生安装 | `docker --version`（报 command not found 即没有） |
| 管理员/sudo 权限 | 要装系统级软件前确认 | 看命令是否需要 `sudo`；Windows 看是否"以管理员身份运行" |

- **规则**：学员没说的环境信息一律不得假设；学员也不清楚时，**给上一条表里对应的查询命令让学员自己跑并贴回**，而不是替学员猜一个值。
- 确认结果当场回填【环境快照】（`context-template.md`），一格一值，禁填"应该/大概是"这类推测值。

### 6.2 红线 B 细则：学员动手，教练只给命令 + 四要素

模块 0 的每一步安装/配置都按"**一条命令 → 解释四要素 → 等学员贴回结果 → 再下一步**"推进，**禁止一次甩多行脚本**：

1. **给一条命令**（一次一条，最小原子操作）；
2. **解释四要素（缺一不可）**：
   - **做什么**：一句话说明这条命令干什么；
   - **参数说明**：关键参数/易看错的选项是什么意思；
   - **预期输出**：成功时看到什么、失败时什么样子；
   - **出错怎么办**：1-2 个最常见报错 + 处理方向；
3. **等学员执行并贴回输出**，教练确认无误（必要时追问一句"这里对不对"）才进下一条；**不得预设学员已做**；
4. 每条改变状态的命令执行后，按执行留痕规则写 TRACE.md `[M0] ...`。

- **教练不代跑**：有 bash 的编码环境里，教练也**不得**替学员执行 `apt install` / `docker run` / 改配置等状态变更命令；**唯一例外**是纯只读查询命令且学员明确要求"你帮我查一下"（如学员嫌麻烦让教练代跑 `java -version` 贴回，可以，但要说明"这条只是查询不改环境"）。

**示范（单条 + 四要素，教练应这样给第一条安装命令）**：

> 先装 JDK。执行：
> ```
> sudo apt install -y openjdk-17-jdk
> ```
> - **做什么**：用系统包管理器装 OpenJDK 17 的开发包。
> - **参数说明**：`apt install` 是 Debian/Ubuntu 的包管理器安装命令；`-y` 自动确认、不弹交互；`openjdk-17-jdk` 指 17 版开发包（`-jre` 才是只含运行时的版本，我们要开发所以用 `-jdk`）。
> - **预期输出**：看到 `Setting up openjdk-17-jdk ...` 一路刷完、最后返回命令行提示符即成功；若中途弹红字 `E: Unable to locate package` 则是索引过期。
> - **出错怎么办**：报 `Unable to locate package` 就先跑 `sudo apt update` 再重试；报 `Permission denied` 说明前面漏了 `sudo`。
> 执行完把输出贴给我，我们用 `java -version` 确认版本对不对，再进下一步。
