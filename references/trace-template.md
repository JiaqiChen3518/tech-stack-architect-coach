# TRACE.md 模板（追加式留痕与术语表载体）

> 本文件是**模板定义**，不是实例。实例由教练在教学/收尾过程中按本格式生成与追加。
> TRACE.md 是 Skill 的**累积过程载体**：与 CONTEXT.md（状态快照，收尾时全文更新）分工——TRACE.md 只追加不重写，承载教学过程中高频增长的「执行留痕」与「术语表」。

---

## 定位与机制

- **存放位置**：默认落盘在**统一项目根目录**，与 `CONTEXT.md` 同级（`{统一项目名}/TRACE.md`；项目即当前工作目录时为 `./TRACE.md`）；
- **更新机制**：**Append 追加，不全文重写**。教学过程中产生新的留痕/术语时，教练当场往对应区段末尾追加，不动历史内容；这与 CONTEXT.md 的"收尾时全文覆盖"恰好互补——CONTEXT.md 负责稳定状态，TRACE.md 负责增长细节；
- **与 CONTEXT.md 的关系**：CONTEXT.md 里只放【留痕与术语指针】指向 `./TRACE.md`（见 `context-template.md`）；冷启动时教练先读 CONTEXT.md 恢复状态，再按需读 TRACE.md（最近 2 个模块留痕 + 全部术语）；
- **落盘工具**：教练用文件工具直接追加写入项目目录；纯对话平台（无文件访问能力）时，由学员手动把追加内容贴进本地 TRACE.md，教练每次只给"要追加的那几行"。
- **防膨胀**：TRACE.md 长度只增不减。若超过约 300 行，收尾时主动向学员建议：把已关闭模块的留痕/术语归档到 `docs/` 笔记中，TRACE.md 只保留最近阶段。

## 【执行留痕】

<!-- 格式：[模块 N] 完整命令原文 → 一句话意图 + 影响范围。当场记录，禁止"等收尾一起补"。 -->

- [M0] `docker run -d --name redis-lab -p 6379:6379 -v /opt/redis/data:/data redis:7.2.5` → 启动课程 Redis 实例，数据目录挂载到宿主，重启不丢数据

## 【已讲术语表】

- RTT：命令往返时间，本机约 0.5ms
- RESP：Redis 序列化协议，文本协议，易解析但体积大于二进制协议

## 填写说明

### 哪个阶段写什么

| 时机 | 写入区段 | 方式 |
|---|---|---|
| 模块 0 搭建/环境验证 | 【执行留痕】 | 当场追加 `[M0] ...` 行；协商确认后首次搭建产生的留痕在路线确认时一次性补齐 |
| 模块教学过程（六步走进行中） | 【执行留痕】+【已讲术语表】 | 执行了须留痕的操作即追加留痕；首次讲到新术语即追加到对应模块组 |
| 收尾（模块/阶段/上下文预警） | 两区段均可补漏 | 与 CONTEXT.md 全文覆盖同时进行：CONTEXT.md 收尾落盘，TRACE.md 补齐本模块遗漏的留痕/术语 |

### 冷启动怎么用

- **默认读取范围**：【已讲术语表】全文（用于回答前核对、避免重复讲解）+【执行留痕】**最近 2 个模块**（用于判断环境状态是否漂移、有无失效配置）；
- **顺序**：先读 CONTEXT.md（状态全貌），再按上述范围读 TRACE.md（细节补充）；
- **与五检查的对应**（见 `session-management.md` §1）：①号检查通读 TRACE.md【执行留痕】、②号检查查 TRACE.md【已讲术语表】、③④⑤读 CONTEXT.md。

### 格式约束

- 【执行留痕】每行严格 `[模块 N] 完整命令原文 → 一句话意图 + 影响范围`，命令原文用行内代码包裹保持可复制；
- 【已讲术语表】按模块分组（如 `### M0-M3`、`### M4`），同一模块组内术语不重复；同一术语在多个模块出现时，归入**首次讲解**它的模块组；
- 区段名与 CONTEXT.md 一样固定（【】内文字不可改名），无内容时填"无"。
