# CONTEXT.md 模板（全局唯一交接文档）

> 本文件是**模板定义**，不是实例。实例由教练在诊断/协商/教学/收尾过程中按本格式生成与更新。
> CONTEXT.md 是 Skill 的唯一持久状态载体：新窗口冷启动、环境排查、进度恢复、偏好生效，全部以它为准。

---

## 格式总则

- **存放位置**：默认落盘在**统一项目根目录**的 `CONTEXT.md`（`{统一项目名}/CONTEXT.md`；项目即当前工作目录时为 `./CONTEXT.md`）；
- **更新机制**：CONTEXT.md 的全文覆盖落盘发生在以下时点（每次都输出全文并落盘）：
  1. 诊断完成；
  2. 路线确认；
  3. 一个模块六步走完成；
  4. 一个阶段完成；
  5. 上下文预警触发收尾。
  教学过程中（模块六步走进行中）不全文更新 CONTEXT.md。过程中产生的高频增长内容（执行留痕、术语表）写入同级的 `TRACE.md`（Append 追加，见 `trace-template.md`）；
- 若 CONTEXT.md 与 TRACE.md 同时存在，冷启动时**优先读 CONTEXT.md 恢复状态**，再按需读 TRACE.md（最近 2 个模块留痕 + 全部术语）；
- 全部区段按下方顺序排列，区段名固定（【】内的文字不可改名、不可合并、不可删除，无内容的区段填"无"）；
- 每次收尾更新输出**全文**（不是增量补丁），放在一个独立的 Markdown 代码块中，末尾标注 `<!-- CONTEXT_END -->`；
- 待办锁定变更时，用 `~~旧任务~~ -> **新任务**` 格式保留变更历史；
- 命令/路径等机器相关内容用行内代码包裹，保持可复制；
- **防膨胀**：每次收尾时教练需目测本文件长度，若超过约 200 行，主动向学员建议把"已关闭的可选项""历史调整记录"等沉淀到 README 或笔记中。

## 各阶段填写说明

| 阶段 | 必须更新的区段 |
|---|---|
| 诊断完成 | 【技术栈配置】【学员画像】【教学偏好】 |
| 路线确认 | 【路线决议】【模块进度】【待办锁定】【环境快照】（含模块 0 搭建留痕） |
| 教学中（每模块） | **仅当次收尾时**更新【模块进度】【当前进度】【项目文件树】【待办锁定】；过程中的留痕/术语写入 TRACE.md（Append 追加，不进 CONTEXT.md） |
| 收尾 | 全部区段 + 【会话状态】（CONTEXT.md 收尾时全文覆盖落盘 + 输出代码块；同时追加 TRACE.md） |
| 冷启动读取 | 读 CONTEXT.md 全部 + TRACE.md 的【已讲术语表】全文 + 【执行留痕】最近 2 模块 |

## 版本兼容

- 旧版交接文档（如原 Redis 模板的 CONTEXT.md）缺少【技术栈配置】【路线决议】【模块进度】【会话状态】时，冷启动按本模板补齐缺失区段——【路线决议】优先从【学员画像】的学习目标与【模块进度】的现有顺序反推，并向学员口述一遍请其确认，再开始教学。
- **旧版含【执行留痕】/【已讲术语表】的 CONTEXT.md 迁移规则**：冷启动时把这两个区段的全部内容搬入同级 `TRACE.md` 的对应区段（【执行留痕】保持 `[模块 N] ...` 原格式，【已讲术语表】按模块分组），CONTEXT.md 里原位置改为【留痕与术语指针】区段指向 `./TRACE.md`。迁移后向学员口述一句"我把留痕和术语表挪到 TRACE.md 了，CONTEXT.md 里留了指针"，再继续。
